# Portable scenes and interactive editing

A scene recipe is a JSON file with schema `alice-eve-scene`, version 1. It contains camera projection and pose (including roll), aspect ratio, colours, sampled colormap RGB tables and fixed colour scales, detector/data selections and per-detector object modes, global and per-detector geometry detail, per-detector openings and opacity, track/cluster sizes, special track IDs and styling, track clipping, materials, lighting and background. It contains no backend, GPU ID, CPU thread count, render resolution or sample count. Input and event defaults are optional; exported scenes omit them unless explicitly requested. Special IDs belong to an event: when changing the input/event, replace them if needed. Missing IDs are recorded in render metadata.

Recipes also preserve `camera_lens_mm`, `view_transform` (`AgX` or `Standard`), exposure in stops, and independent `track_emission` / `cluster_emission`. **Display colours**, **Exposure**, **Track glow** and **Cluster glow** update the interactive scene and export unchanged. Older recipes retain AgX and the previous emission defaults. Standard preserves saturated blue more directly; AgX compresses highlights. Desktop **Focal length (mm)** updates a loaded camera pose without discarding its position/rotation.

Fresh desktop installations use the [commissioning interior preset](REFERENCE-RECREATION.md), the best of five reference trials. Saved local preferences take priority. **Appearance → Use commissioning defaults** restores this style for the current input/event and local aligned assets. This preset deliberately uses an interior camera, roll and 180° openings; **Show complete detectors** restores complete geometry.

## Desktop workflow

1. Load data and select an event. Select detector surfaces and L3 independently; supply the corresponding geometry assets.
2. Click **Interactive scene…**. Blender preserves the selected Geometry detail (full aligned surfaces or coarse cells) and opens an Eevee rendered viewport. Hidden placement/prototype helpers remain hidden, and blended transparency avoids hashed speckles. Open the **ALICE EVE** tab in the right sidebar (N toggles the sidebar).
3. Orbit, pan and zoom; the editor enables Blender's trackball rotation for arbitrary orientation; click **Use current view as camera** to make that view the render camera. The sidebar button captures the viewport through its WINDOW region; if already viewing the render camera, it leaves the existing camera unchanged. **Navigate render camera** is enabled by default: zoom, pan and orbit move the actual render camera. The camera frame defines the final crop. Disabling this control enables frame inspection; inspection magnification alone is not a render-camera change. [Blender camera-view navigation](https://docs.blender.org/manual/en/5.0/editors/3dview/navigate/camera_view.html) describes this distinction. Export and Render full also capture a non-camera perspective viewport before saving the recipe. Edit camera rotation directly or use **Roll −15° / +15°**, including when looking along the beam pipe. The desktop Render tab also has **Camera roll (°)**. **Level camera (Y up)** removes roll without moving the camera or changing its viewing direction. New default orbits use Y as vertical and elevation 0°, so the XZ plane and beam axis appear horizontally. Camera lens/projection can be edited directly. Export preserves camera position, rotation, lens, orthographic scale, sensor dimensions/fit, shifts and clipping distances. Resolution changes keep the same normalized framing. Change light positions/rotations, power, size and colour in the sidebar.
4. Click **Full aligned surfaces** for the natural detector structures used in the reference renders. **Make geometry opaque** sets opacity to 1; lower each detector's Opacity for a translucent view. A detector does not have to be selected at launch: enable its **Surface** checkbox later, and the editor loads its asset automatically. Detector data availability does not restrict geometry availability. If no aligned asset was supplied, choose one in its **Aligned geometry asset** field first. Only selected surfaces are loaded. Choose **Existing surfaces**, **Outer shell** or **Outline** per detector and click **Apply geometry appearance**. Shell/outline use an approximate convex hull and may fill beam holes or bridge disconnected structures; keep Existing surfaces for physical geometry. Set detector opening angles, colours, opacity, shading and background. Openings remove an angular wedge around global Z, centred on −Y: 0° keeps the full surface; 180° opens the −Y half; 360° hides the surface. These live openings use a global-position shader mask, including instanced geometry.
5. Use **Select no detectors** to clear event data and surfaces, including L3. **Show complete detectors** sets all opening angles to 0°. Each detector has an **Objects** selector for tracks/clusters/both; **Set all object modes** is a bulk shortcut. Set **Track linewidth (cm)** to change the physical line diameter; it updates the viewport immediately. Detector selection and linewidth changes refresh clipping after a brief delay. Enter comma-separated **Special track IDs**, or click **Pick tracks with mouse**: plain click replaces the list, Ctrl-click adds, Shift-click toggles, **Stop picking (Esc)** or Esc stops. Sidebar clicks pass through the selection handler. Picking tests displayed curve centrelines within 10 screen pixels, with nearer depth breaking ties; transparent surfaces do not block picking. Special linewidth and linked-cluster radius apply only to listed track IDs and explicit cluster `track_id` associations. Disable **Use special colours** to retain colormap colouring while emphasizing sizes. Select event data and colour quantities. Click **Apply data selection / colour coding** after changing colouring or palette. Unavailable detector data is disabled; unsupported colour quantities produce a diagnostic. Fixed scalar ranges keep identical colour coding when another event is rendered.
6. Click **Export config** to save the current scene without choosing quality. Optionally include a default input/event. **Render full** opens a resolution slider and sampling dialog. Resolution is a linear percentage of a maximum 7680 × 4320 canvas: 25% = 1920 × 1080, 50% = 3840 × 2160, 100% = 7680 × 4320 for 16:9. Other camera aspect ratios fit inside that canvas without changing the crop. The dialog recommends an available backend/preset, and offers **Keep current scene**, **Full aligned surfaces**, **Simplified aligned cells**, or **Schematic envelope** independently for each selected detector and L3. Keep current scene preserves the preview type/detail/appearance. Explicit choices replace those settings: Full loads actual aligned surfaces even from a schematic, coarse-cell or outline preview; Simplified loads aligned assets and reduces them to cells; Schematic uses approximate envelopes. Aligned choices require assets and stop at preflight when they are missing. Prerequisites are checked before starting a separate render process. Render-only detail choices leave the interactive view unchanged and are saved in `full-render-config.json` beside the editor files; the renderer receives a separate immutable copy of that recipe for each launch, so another render cannot change the pending job’s settings. To keep mixed detail in an ordinary exported scene, use the per-detector Geometry detail controls and Apply geometry appearance before exporting. Progress and any failure details are in the displayed `full-render.log` location.

The Qt application also has **Export config…** and **Load config…**. A loaded config keeps its exact camera matrix until you edit the camera position controls. Geometry detail can be selected as full or simplified. Quality and per-detector/magnet geometry detail are chosen by the full-render dialog; preview is capped at 640px/16 samples.

Full aligned surfaces preserve the native detector structures and can be heavier to navigate. For a look similar to the run-560067 reference images, use full ITS/TPC geometry, an approximately 180° opening and opacity around 0.035 (or increase opacity to make surfaces more solid).

The optional simplified mode derives spatial cell bounds from the actual aligned surfaces. It reduces each detector to one mesh with at most 256 coarse cells, rather than millions of repeated small shapes. It is explicitly an approximation: small structures and curved surface detail are lost. Exported scenes retain that detail choice so the final render has the same surfaces. Choose full geometry and export another recipe when physical surface detail is needed. Simplifying geometry does not reduce the number of event objects; dense cluster displays can still need substantial memory.

## Recent scenes, favourites and reuse

The desktop UI has recent/favourite pickers above the input/event table and separate **Recent scenes** and **Favourites** tabs. Completed previews/full renders save a portable recipe with the actual render camera and colour ranges. New interactive sessions automatically save their current camera and scene settings every two seconds; Export config also registers its exact snapshot. The desktop lists update while Blender is open. **Refresh** discovers older outputs in the selected output directory, including older exported editor scenes.

**Add to favourites…** stores a named, fixed snapshot. Further edits to the source session do not change that favourite. Remove it from the Favourites tab if no longer needed. **Reload scene and original event** uses the stored input/event reference and checks the original aligned asset hashes. **Use for current input / event** clones the scene appearance while leaving the input path and selected events untouched. You can enter/load a new data path, select its event, then use either picker. The current local geometry assets/units are retained so the new event can use its own alignment bundle. Event-specific highlighted track IDs are cleared; their style settings remain. Unsupported colour quantities are reported by preflight rather than silently changing the requested coding.

Recipes remain platform-independent. The history database (`scene-library.local.sqlite`) and favourite copies (`scene-library/favourites`) are local to this installation and ignored by Git; they store recipes and local data/asset references, without copying event data or geometry. To transfer a scene to another machine, Export config and provide that machine's input/event and matching geometry assets.

## Track extents

**Clip tracks to selected detectors** is enabled by default. The renderer selects eligible fitted tracks by their source detectors, then trims sampled polylines to the selected sources' outer envelopes. When detector surfaces are shown, that surface selection restricts the eligible clipping detectors; otherwise it uses the data selection. L3 does not define a track limit. Intersections between sampled points are interpolated, and disconnected pieces remain separate.

For real data, extent planes come from the actual aligned prototype vertices and every global instance transform: 64 azimuth support planes plus global Z bounds. They describe a conservative outer envelope, rather than active detector material or a hit-association test. Internal holes and gaps within one detector are not a display veto. No source points, fitted kinematics or input data are modified. Approximate dimension-based bounds are used only for explicitly schematic geometry or synthetic demos.

The linewidth is the tube diameter in cm; the JSON field `track_radius_cm` stores half that value for compatibility. Clipping leaves a radius margin at the outer boundary. Quality/resolution changes preserve the physical diameter. Clipping can be disabled explicitly to display the full sampled trajectory.

The selected detector assets are needed for real track clipping even if their surfaces are hidden. Portable config exports include those assets' references and hashes. Missing assets are reported by preflight before the Blender render starts.

## Move to another computer

Copy the scene JSON and the selected detector geometry files. Data can be copied separately, or select a different local input/event. Geometry references contain basenames and SHA-256 hashes, not the originating computer's absolute paths. `--geometry-root` locates a geometry bundle on the destination; hashes enforce the same alignment and surfaces. A local `--assets` JSON mapping can point individual detectors to different folders; it cannot bypass the hash check.

After installing this project and Blender, one command starts the full render:

```sh
alice-render render-config scene.json --input /local/events.jsonl.gz --event RUN-TF-PV-ID --geometry-root /local/geometry --quality final --resolution-percent 50 --backend AUTO --output renders
```

Use the event ID listed in the catalogue, or explicitly use `--event ordinal:0`. Command-line input/event values override optional config defaults. Relative default input paths are resolved beside the config. An omitted input/event without a default is an error. Raw TF/CTF inputs additionally require `--profile /local/ingest.json` for a configured O2 environment; exported event data renders without O2.

```sh
alice-render edit-config scene.json --input /local/events.jsonl.gz --event ordinal:0 --geometry-root /local/geometry
```

This reopens the interactive scene from its recipe, rather than relying on saved Blender UI state.

Height follows the stored aspect ratio. Override with `--width`, `--height`, `--samples`; changing aspect ratio deliberately changes framing. GUI custom quality provides the same controls. Recommendations start CPUs at draft and detected GPUs at balanced, rather than predicting timings or VRAM capacity. AUTO selects an actually discovered OptiX, Metal, HIP, CUDA or CPU backend, in that order. Explicit unavailable backends produce an error without fallback.

The same recipe reproduces camera, scene geometry, lights, materials and scalar ranges. CPU/GPU numerical differences, stochastic sampling, denoising and Blender-version colour management can change pixels; bit-identical PNGs across backends are not promised. Use the same Blender version for closest matching output. Recipe schema/geometry mismatches stop before rendering.

All colormaps in the host Matplotlib registry are available (182 here, including reversed maps). Exported recipes carry a sampled 256-entry RGB table, so the receiving Blender instance does not need Matplotlib or a matching palette registry. Custom transferred palettes retain their table when loaded; choosing another palette replaces it.

The **matching** quantity has range 0–1: 1 identifies a composite O2 fitted-source record such as ITS-TPC or ITS-TPC-TOF; 0 identifies a standalone fitted-source record. Unknown records are grey. This does not assert that a standalone ITS/TPC record never participates as a component in another match. Explicitly associated clusters inherit their fitted track’s status. Arbitrary detector sets or positions are not used to infer a match.

`geometry_lod` supplies the scene default (`full` or `simplified`). Optional `geometry_lods` overrides it by detector name, including `L3`; omitted entries inherit the default. Both interfaces preserve these overrides on scene load/export. The desktop full-render dialog also offers per-surface detail choices for the new render, recorded in its job settings.

## Camera convention and input density

ALICE event and geometry coordinates remain global XYZ; Y is vertical and Z is the beam. `camera_orbit_axis: "Y"` makes azimuth rotate around Y and elevation rise above the XZ plane. General programmatic settings default to zero elevation and zero roll; the desktop commissioning preset supplies its tested interior camera and roll. `"Z"` retains the historical orbit convention. Older portable recipes without this field keep their historical framing, including explicit camera matrices; untouched old local UI defaults are upgraded, while custom camera settings are preserved.

The event table now shows **PV contributors**, and the Blender sidebar shows input fitted-track and cluster counts per detector. Counts include matched fitted sources in each constituent detector and are taken before display selection/clipping. They do not imply that standalone TPC tracks have ITS measurements. TPC-only polylines in the O2 export begin near the TPC inner radius; the renderer does not fabricate inward ITS segments. Choose another collision for a denser ITS view. In the validated raw run-560067 file, event `560067:2619419:212036032:5` has 3 ITS-associated drawable fitted records and 3 PV contributors; event `560067:2619419:212036032:4` has 4,926 ITS-associated drawable fitted records and 4,161 PV contributors. These are fitted-record counts, not a deduplicated physical-particle count.

`geometry_schematics` supplies optional per-detector booleans (including `L3`) that override the legacy global `schematic` default. An explicit aligned choice writes `false` here, preventing a schematic preview from overriding the final selection. Portable configs include hash-checked assets required by the effective choices. Optional local `--assets` entries also remain available when a schematic recipe is reopened and subsequently upgraded to aligned rendering.
